# EdNet 데이터 사전

작성일: 2026-10-08
출처: [EdNet 공식 저장소](https://github.com/riiid/ednet), [데이터 논문](https://arxiv.org/abs/1912.03072)
이용 조건: CC BY-NC 4.0 (비상업적 연구 목적, 출처 표시)

EdNet은 토익 학습 서비스 산타(Santa)가 수집한 학생의 학습 기록이다. KT1부터 KT4까지 네 단계로 제공되며, 모든 단계는 학생 한 명당 CSV 파일 하나로 나뉘어 있다.

이 문서는 공식 문서를 읽고 실제 파일을 열어 확인한 내용을 정리한 것이다.

- KT1, KT2: 학생 5명(u1~u5)의 실제 파일을 열어 구조를 확인했다.
- KT3, KT4: 아직 실제 파일을 열어 보지 않았다. 공식 문서에만 근거하며, 전체 데이터를 합쳐 확인하면서 고쳐 나갈 예정이다.
- Contents: 아직 실제 파일을 열어 보지 않았다. 공식 문서에만 근거한다.

| 단계 | 담긴 내용 | 수집 시작 | 파일 수 |
|---|---|---|---|
| KT1 | 문제 풀이 기록 (문제당 한 줄) | 2017-04-18 | 784,309 |
| KT2 | 문제를 푸는 과정의 행동 (행동당 한 줄) | 2018-08-27 | 297,444 |
| KT3 | KT2 + 해설 읽기, 강의 시청 | 2018-08-27 | 297,915 |
| KT4 | KT3 + 선택지 지우기, 음성·영상 재생, 결제, 환불, 쿠폰 | 2018-08-27 | 297,915 |
| Contents | 문제, 강의, 결제 상품, 쿠폰 정보 | | 4 |

수집 시작일과 파일 수는 공식 문서 기준이다.

## KT1

문제 풀이 기록.

### 한 줄의 뜻

학생 한 명이 문제 하나에 답한 기록

### 컬럼

| 컬럼 | 뜻 | 형식 | 단위 |
|---|---|---|---|
| `timestamp` | 문제가 학생에게 제시된 시각 | 정수 (유닉스 시각) | 밀리초 |
| `solving_id` | 그 학생이 문제 묶음을 푼 순번 | 1부터 시작하는 정수 | |
| `question_id` | 문제 ID | `q{정수}` | |
| `user_answer` | 학생이 제출한 답 | `a`~`d` 중 한 글자 | |
| `elapsed_time` | 문제를 푸는 데 걸린 시간 | 정수 | 밀리초 |

학생 ID는 컬럼에 없고 파일 이름(`u{정수}.csv`)에 있다.

| 1565096221062 | 2 | q4706 | c | 24000 |
| 1565096293432 | 3 | q4366 | b | 68000 |
| 1565096339668 | 4 | q4829 | a | 42000 |
| 1565096401774 | 5 | q6528 | b | 59000 |

## KT2

문제를 푸는 과정의 행동 기록.

KT1은 문제마다 최종 답만 남기지만, KT2는 묶음을 열고, 답을 고르고, 제출하는 행동을 하나씩 기록한다. 그래서 답을 고친 과정을 알 수 있다.

### 한 줄의 뜻

학생이 한 행동 하나

### 컬럼

| 컬럼 | 뜻 | 형식 | 단위 |
|---|---|---|---|
| `timestamp` | 행동이 일어난 시각 | 정수 (유닉스 시각) | 밀리초 |
| `action_type` | 행동의 종류 | `enter`, `respond`, `submit` | |
| `item_id` | 행동의 대상 | `b{정수}` 또는 `q{정수}` | |
| `source` | 문제를 푼 경로 | 문자열 | |
| `user_answer` | 학생이 고른 답. `respond`일 때만 값이 있음 | `a`~`d` 중 한 글자 | |
| `platform` | 접속 환경 | `mobile` 또는 `web` | |

학생 ID는 컬럼에 없고 파일 이름(`u{정수}.csv`)에 있다.

### action_type의 값

| 값 | 뜻 | 이때 `item_id`에 들어가는 것 |
|---|---|---|
| `enter` | 문제 묶음이 화면에 뜸 | 묶음 ID (`b…`) |
| `respond` | 문제 하나에 답을 고름. 같은 문제에 여러 번 할 수 있고, 제출 직전의 마지막 응답이 최종 답 | 문제 ID (`q…`) |
| `submit` | 묶음의 최종 답을 제출 | 묶음 ID (`b…`) |

### source의 값

| 값 | 뜻 | 근거 |
|---|---|---|
| `sprint` | 학생이 공부할 파트를 직접 고르고 그 파트의 문제만 풂 | 문서, 실제 파일에 값 있음 |
| `todays_recommendation::sprint`, `todays_recommendation::review_quiz` | 오늘의 추천. 예측 정답 확률에 맞춰 매일 문제를 추천 | 문서 |
| `adaptive_offer` | 특정 태그의 오답이 기준을 넘거나 정답률이 떨어지면 그 태그의 강의와 문제를 제안 | 문서 |
| `tutor` | 전체 파트에서 알고리즘이 추천한 문제를 풂 | 문서 |
| `in_review` | 이미 푼 문제를 다시 풂 | 문서 |
| `diagnosis` | 공식 문서에 정의 없음 (주의할 사항 5-1 참고) | 실제 파일에 값 있음 |

### 예시

학생 `u1`의 처음 다섯 줄 (실제 파일)

| timestamp | action_type | item_id | source | user_answer | platform |
|---|---|---|---|---|---|
| 1565096151269 | enter | b3544 | diagnosis | | mobile |
| 1565096187972 | respond | q5012 | diagnosis | b | mobile |
| 1565096194904 | submit | b3544 | diagnosis | | mobile |
| 1565096195001 | enter | b3238 | diagnosis | | mobile |
| 1565096218682 | respond | q4706 | diagnosis | c | mobile |

## KT3

KT2에 해설 읽기와 강의 시청이 더해진 기록. **이 절은 공식 문서에만 근거하며 실제 파일로 확인하지 않았다.**

문제를 푼 뒤에 해설을 얼마나 읽었는지, 강의를 봤는지를 알 수 있다.

### 한 줄의 뜻

학생이 한 행동 하나

### 컬럼

KT2와 같다. (`timestamp`, `action_type`, `item_id`, `source`, `user_answer`, `platform`)

### 추가되는 행동

| 대상 | action_type | 뜻 | 이때 `item_id`에 들어가는 것 |
|---|---|---|---|
| 해설 | `enter` | 해설 화면에 들어감 | 해설 ID (`e…`). 번호는 묶음 ID와 같음 |
| 해설 | `quit` | 해설 화면에서 나옴 | 해설 ID (`e…`) |
| 강의 | `enter` | 강의 영상을 재생 | 강의 ID (`l…`) |
| 강의 | `quit` | 강의 시청을 멈춤 | 강의 ID (`l…`) |

`enter`와 `quit`의 시각 차이로 해설이나 강의를 본 시간을 계산할 수 있다.

### 추가되는 source의 값

| 값 | 뜻 |
|---|---|
| `after_sprint` | 스프린트에서 푼 문제의 해설 |
| `after_review` | 복습에서 푼 문제의 해설 |
| `my_note` | 이미 푼 문제의 해설을 다시 읽음 |
| `archive` | 전체 강의 목록에서 강의를 직접 골라 봄 |
| `todays_recommendation::lecture` | 오늘의 추천으로 제안된 강의 |
| `adaptive_offer` | 오답이 쌓였을 때 제안된 강의 (KT2에도 있는 값) |

## KT4

KT3에 선택지 지우기, 음성·영상 재생, 결제, 환불, 쿠폰이 더해진 기록. 산타가 수집한 행동 전체다. **이 절은 공식 문서에만 근거하며 실제 파일로 확인하지 않았다.**

결제 여부를 알 수 있는 유일한 단계다.

### 한 줄의 뜻

학생이 한 행동 하나

### 컬럼

KT3의 컬럼에 `cursor_time`이 추가된다.

| 컬럼 | 뜻 | 형식 | 단위 |
|---|---|---|---|
| `timestamp` | 행동이 일어난 시각 | 정수 (유닉스 시각) | 밀리초 |
| `action_type` | 행동의 종류 | 문자열 | |
| `item_id` | 행동의 대상 | `b`, `q`, `e`, `l`, `p`, `c`로 시작하는 ID | |
| `cursor_time` | 음성·영상을 재생하거나 멈춘 지점. 문서 예시에서는 재생·정지 행동에만 값이 있음 | 정수 | 밀리초로 추정 (문서에 단위 없음) |

## Contents

문제, 강의, 결제 상품, 쿠폰의 정보를 담은 표 4개. **이 절은 공식 문서에만 근거하며 실제 파일로 확인하지 않았다.**

공식 문서는 콘텐츠를 문제, 강의, 결제 상품, 쿠폰, 점수 다섯 종류로 소개하지만, 점수는 공개되지 않아 파일은 4개다.

KT1~KT4의 기록에 이 표들을 연결해서 정답 여부, 묶음, 파트, 태그, 강의 길이, 결제 상품의 종류를 붙인다.

## 주의할 사항

### 1. 모든 단계에 해당하는 것

**1-1. 학생 번호가 파일 이름에만 있다.**
파일 안에는 학생 ID 컬럼이 없다. 여러 파일을 합칠 때 파일 이름을 컬럼으로 함께 가져오지 않으면 어느 줄이 어느 학생의 기록인지 알 수 없다. (실제 파일로 확인)

**1-2. 시각은 실제 값이 아니다.**
공식 문서에 따르면 보안 문제로 시각을 일정 값만큼 옮겨 놓았다. 행동 사이의 간격은 보존되지만, 몇 시에 공부했는지는 그대로 믿을 수 없다. 열어 본 KT1, KT2 파일은 2019년으로 표시되고, 문서의 KT2, KT4 예시는 2013년으로 표시된다. 얼마나, 어떤 방식으로 옮겨졌는지는 확인하지 못했다.

**1-3. 시간 관련 값은 밀리초다.**
`timestamp`와 `elapsed_time`은 밀리초라서 1,000으로 나눠야 초가 된다. `cursor_time`도 밀리초로 보이지만 공식 문서에 단위가 적혀 있지 않다.

**1-4. KT1과 KT2~KT4는 대상 학생과 기간이 다르다.**
KT2~KT4는 2018-08-27 이후의 기록만 담는다. 학생 수도 KT1(약 78만 명)의 40%에 못 미친다(약 30만 명). 단계를 섞어 쓸 때는 대상이 같은지 확인해야 한다.

**1-5. 실제 토익 점수가 없다.**
공식 문서에 점수는 "공개 예정"으로만 되어 있고 제공되지 않는다. 학생의 실력을 나타내는 값을 직접 정의해야 한다.

**1-6. 문제를 앱이 골라 준다.**
산타는 학생의 예측 정답 확률에 맞춰 문제를 추천하고, 오답이 쌓인 유형의 문제를 따로 제안한다. 학생마다 받은 문제의 난이도가 다르므로 정답률을 그대로 비교하면 안 된다. 문제의 경로(`source`)와 난이도를 함께 고려해야 한다.

**1-7. 무료 사용자는 풀 수 있는 문제가 제한된다.**
공식 문서에 따르면 무료 사용자는 매일 파트 2와 파트 5의 문제를 정해진 수만큼만 받고, 결제하면 모든 파트의 문제를 풀 수 있다. 무료와 유료를 나누지 않고 풀이량이나 정답률을 비교하면 결과가 왜곡된다. 결제 여부는 KT4에서만 알 수 있다.

### 2. KT1

**2-1. `solving_id`는 학생마다 1부터 새로 시작한다.**
여러 학생을 합친 뒤에는 반드시 학생 ID와 함께 써야 한다. `solving_id`만으로 묶으면 서로 다른 학생의 기록이 섞인다.

**2-2. 문제는 묶음으로 제공된다.**
묶음은 같은 지문·그림·듣기 자료를 공유하는 문제들이다. 같은 묶음의 문제들은 같은 `solving_id`를 가지므로, 한 `solving_id`에 여러 줄이 있을 수 있다. KT1에는 묶음 ID 컬럼이 없다.

**2-3. 정답 여부가 없다.**
학생이 고른 답만 있다. 문제 표의 정답과 비교해야 맞았는지 알 수 있다.

**2-4. `elapsed_time`이 무엇을 잰 것인지 불분명하다.**
같은 풀이에 대해 KT2의 `enter`부터 `submit`까지의 간격과 비교하면 비슷하지만 일치하지 않는다(학생 u1의 첫 풀이: 43.6초 대 38초). 공식 문서의 예시에서는 같은 묶음의 문제들이 같은 값을 갖는다. 묶음 단위로 잰 값이 줄마다 반복된 것이라면, 단순히 더할 경우 시간이 부풀려진다.

### 3. KT2~KT4

**3-1. `item_id`가 가리키는 것은 행동에 따라 다르다.**

| 첫 글자 | 가리키는 것 | 근거 |
|---|---|---|
| `b` | 문제 묶음 | 실제 파일로 확인 |
| `q` | 문제 | 실제 파일로 확인 |
| `e` | 해설 | 문서 |
| `l` | 강의 | 문서 |
| `p` | 결제 상품 | 문서 |
| `c` | 쿠폰 | 문서 |

**3-2. `enter`는 여러 대상에 쓰인다.**
묶음을 열 때, 해설을 열 때, 강의를 재생할 때 모두 `enter`로 기록된다. `action_type`만 보고 세면 안 되고 `item_id`의 첫 글자를 함께 봐야 한다.

**3-3. 최종 답은 마지막 `respond`다.**
같은 문제에 `respond`가 여러 번 나올 수 있다. 정답 여부를 계산할 때는 제출 직전의 마지막 응답만 써야 한다. (답을 고친 사례는 실제 파일로 확인)

**3-4. `user_answer`의 뜻이 행동에 따라 다르다.**
`respond`에서는 고른 답이고, 선택지 지우기에서는 지운 선택지다. 정답 여부는 `respond` 줄로만 계산해야 한다.

**3-5. `quit`이 없는 경우가 있을 수 있다.**
해설이나 강의를 본 시간은 `enter`와 `quit`의 차이로 계산한다. 학생이 앱을 그냥 꺼 버리면 `quit`이 기록되지 않을 수 있고, 그러면 시간을 계산할 수 없거나 길게 잡힌다. 추정이며, 실제 파일에서 `enter`와 `quit`이 짝을 이루는 비율을 확인해야 한다.

### 4. Contents

**4-1. 값이 없을 때 `-1`로 기록된다.**
강의 표의 `tags`, `video_length`, `deployed_at`은 값이 없으면 `-1`이다. 결제 상품 표의 `duration`과 `number_of_questions`도 해당하지 않는 상품에는 `-1`이 들어간다. 비어 있는 값이 아니라 숫자이므로, 평균이나 합계를 내기 전에 걸러야 한다.

**4-2. 파트 2는 보기가 3개, 나머지 파트는 4개다.**
찍어서 맞힐 확률이 파트 2는 약 33%, 나머지는 25%다. 파트를 섞어 정답률을 비교하면 파트 2를 많이 푼 학생이 유리해 보인다. 무료 사용자가 파트 2와 5의 문제만 받는다는 점(1-7)과 겹친다.

**4-3. 문제의 태그는 여러 개, 강의의 태그는 하나다.**
문제는 `{정수};{정수};…` 형식으로 태그가 여러 개 붙고, 같은 묶음의 문제라도 태그 조합이 다를 수 있다. 태그별로 집계하면 한 문제가 여러 태그에 중복으로 세어진다. 문제와 강의는 같은 태그 체계를 쓰므로 태그로 서로 연결할 수 있다.

**4-4. 쿠폰으로도 이용 기간이 생긴다.**
쿠폰에는 이용 기간(`duration`)이 있다. 공식 문서 예시에서 쿠폰 c16과 결제 상품 p6은 둘 다 180일이다. 결제(`pay`)만 보고 무료·유료를 나누면 쿠폰으로 이용한 학생이 무료로 분류된다. 쿠폰 종류(`type-{정수}`)의 뜻은 "출처에 따라 정해진다"고만 되어 있어 알 수 없다.

**4-5. 결제 금액이 없다.**
결제 상품 표에는 종류와 기간(또는 수량)만 있고 가격이 없다. 결제 여부와 상품 종류는 알 수 있지만 매출은 계산할 수 없다.

**4-6. `deployed_at`의 뜻을 확신할 수 없다.**
문서는 "산타에서 제공되기 시작한 시각"이라고 하지만, 문제 표와 강의 표의 예시 값은 2019년 10월이다. KT1은 2017년 4월부터 수집됐으므로 그보다 앞서 쓰인 문제도 있었을 것이다. 다시 등록된 시각일 수 있고, 시각이 옮겨졌는지도 문서에 없다.

### 5. 공식 문서의 오류와 불일치

공식 문서에는 본문과 예시가 서로 다른 곳이 여러 군데 있다. 문서는 출발점으로만 쓰고 실제 파일을 기준으로 삼는다.

**5-1. `source`의 `diagnosis`는 정의가 없다.**
문서의 경로 목록에는 빠져 있고 예시 표와 실제 파일에만 나온다. 학생 u1의 기록이 이 값으로 시작하는 것으로 보아 가입 직후의 진단 테스트로 추정하지만 확인하지 못했다. 분석에 쓰기 전에 데이터로 확인해야 한다.

| 번호 | 위치 | 내용 | 상태 |
|---|---|---|---|
| 5-2 | KT1 예시 표 | 머리글이 `question_id`, `bundle_id`로 되어 있으나 실제 컬럼은 `solving_id`, `question_id` | 실제 파일로 확인 |
| 5-3 | KT3 강의 설명 | 강의 경로가 "두 가지"라고 하고 세 개를 나열. `todays_recommendatin`으로 철자 오류 | 실제 값 확인 필요 |
| 5-4 | KT3 본문과 예시 | 본문은 스프린트 해설의 경로가 `after_sprint`라고 하는데, 예시 표에서는 `sprint`로 되어 있음 | 실제 값 확인 필요 |
| 5-5 | KT4 본문과 예시 | 본문은 `erase_choice`, 예시 표는 `eliminate_choice` | 실제 값 확인 필요 |
| 5-6 | KT4 예시 표 | `text_enter`라는 행동이 나오지만 본문에 정의가 없음 | 실제 값 확인 필요 |
| 5-7 | KT4 무료 제공량 | "10 questions of Part 2 and 5 each daily"가 모호함. 파트 2와 5 각각 10개로 해석했으나 확정할 수 없음 | 데이터로 확인 필요 |
| 5-8 | 결제 상품 표 | 본문의 컬럼 이름은 `number_of_questions`(풀 수 있는 문제 수)인데 예시 표 머리글은 `number_of_bundles`다. KT4 본문도 paygo를 "`number_of_bundles`에 적힌 수만큼의 묶음"으로 설명한다. 컬럼 이름도, 세는 단위(문제인지 묶음인지)도 엇갈린다 | 실제 파일 확인 필요 |
| 5-9 | Contents 규격 | 압축 파일 크기(0.6MB)가 압축을 푼 크기(0.1MB)보다 크게 적혀 있다 | 분석에는 영향 없음 |
